# 设计原则

OryxOS 的每个技术决策都回溯到这七条原则。

## 底座优先于 Agent

最重要的交付不是某个强大的 Agent，而是让任意 Agent 都能可靠运行的环境。单个 Agent 的能力上限由模型决定，而一群 Agent 能否上生产，由底座决定。

## 自实现核心，可控优先

核心推理循环（ReActLoop）自己实现，不套外部 Agent 框架，循环行为完全可控；底层模型协议适配复用成熟库（Spring AI Alibaba，仅用协议转换 + `@Tool` schema 生成），不重复造轮子。

## 配置即 Agent

一个 Agent 由一份配置（一个目录）定义，而不是由代码写出。`AGENT.md` 的 frontmatter 是运行配置，正文是任务指令——最懂业务的人不需要写代码就能定义 Agent。

## 对接开放标准

工具用 MCP、Agent 协作用 A2A、技能用开放格式（借 Anthropic Agent Skills 目录形态），与生态协同，不另立协议。私有协议会把用户锁在 OryxOS 里，这与项目的定位相悖。

## 无状态实例，状态外置

实例本身不持有状态：Session、审计与长期记忆（SQLite 档）落 SQLite，Agent 目录与记忆落文件系统，定时任务的定义源是 `AGENT.md`。这是从单机平滑走向分布式的前提——从架构第一天就把路留好。

## 安全是地基不是补丁

工具来源受控、最小权限、强制沙箱、凭证不落地、全链路可审计——安全从第一天就在架构里，不是事后补的一层壳。

## 分阶段克制

当前只做运行时内核的最小完备集，治理与重型分布式基础设施留到后续阶段。每次架构升级都必须用真实使用数据证明其必要性——慢就是快，克制且聚焦。
